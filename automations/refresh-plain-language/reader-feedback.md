# Reader Feedback — user-owned

**The user hand-edits this file.** Every prose-writing skill reads it (`/refresh-market-news`, `/refresh-deep-analysis`) and so does `/refresh-plain-language`. No automation may ever write to it.

This is the override channel. When something on the site did not make sense to you — a word you had to look up, a sentence you had to read twice, a paragraph that told you a fact but not why you should care — write one line here. The next run treats it as law.

It is deliberately **not** inside `automations/refresh-deep-analysis/memory/`: that directory belongs to one skill, and this feedback binds all of them.

## How this differs from the other two feedback files

| File | Who writes it | What belongs there |
|---|---|---|
| **`reader-feedback.md`** (this file) | you | *comprehension* — "I did not understand X" |
| `memory/editorial-lessons.md` | you | *analysis* — framing, emphasis, what to cover |
| `drafter-notes.md` | the Editor, replaced each run | what the Editor had to fix, and what it could not fix without sources |

## How to use

One line per lesson: `YYYY-MM-DD — lesson. (Why: 1-line context.)`

You do not have to be precise about the fix — naming the confusion is enough. "I didn't know what cloture was" is a better note than a proposed rewrite.

Example forms:
- `2026-08-21 — I had to look up "cloture". (Why: used seven times, never defined.)`
- `2026-08-21 — the Analysis body told me Strategy sold coins but not whether that is bad for me. (Why: consequence was missing.)`
- `2026-08-21 — "$100M per sale" meant nothing until I saw it next to a weekly ETF number. (Why: numbers need a yardstick.)`
